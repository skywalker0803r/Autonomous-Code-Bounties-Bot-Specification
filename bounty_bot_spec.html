一、 系統概述與硬體適配

本系統旨在建立一套完全自動化的開源懸賞（Code Bounties）機器人。系統自動監控 Algora / GitHub 上帶有懸賞標籤的 Issue，進行 AST 靜態語法分析與上下文提取，結合 LLM API (如 Gemini / Claude) 自動生成 Bug 修復補丁，並在本地 Docker 容器中執行自動化測試驗證，最終自動送出 PR 獲取懸賞金。

硬體環境 Intel i5-6400 (4C/4T) | 16GB RAM | GTX 1050 Ti (4GB) | 240GB SSD
軟體依賴 Windows 10 / WSL2 (Ubuntu 22.04 LTS), Docker, Python 3.10+, Git, GitHub CLI (gh)
核心架構 Event Monitor → Code Ingestion → AST/LLM Repair → Docker Sandbox CI → Auto PR Submit

二、 系統核心模組與目錄架構

Gemini CLI 請依據以下目錄結構建置整個 Python 專案：

bounty_bot/
├── config/
│   └── settings.yaml          # API Keys, Filter Criteria, Target Platforms
├── src/
│   ├── __init__.py
│   ├── monitor.py             # Algora/GitHub Issue 監控模組
│   ├── ingestor.py            # Repo 克隆、環境檢測與 AST/Context 解析
│   ├── solver.py              # LLM Patch 生成與程式碼修正邏輯
│   ├── tester.py              # Docker 隔離沙盒與 Unit Test 自動驗證
│   └── submitter.py           # Git Branch、Commit & Auto PR 提交
├── docker/
│   └── sandbox.Dockerfile     # 本地 CI 測試通用沙盒環境
├── main.py                    # 主入口點 (24/7 自動排程循環)
└── requirements.txt

三、 各模組開發規格指示 (System Specifications)

1. Issue 監控模組 (src/monitor.py)

  • 自動輪詢 Algora API (https://api.algora.io/v1/bounties) 與 GitHub REST API。
  • 過濾條件：僅選取語言包含 Python、TypeScript、JavaScript 且懸賞金額 ≥ $50 的 Open Issues。
  • 排除含有「Needs Discussion」、「Design Required」等模糊需求標籤，專注於明確的 Bug Fix / Unit Test 失敗項目。

2. 代碼解析與 AST 提取模組 (src/ingestor.py)

  • 利用 git clone --depth 1 將目標倉庫下載至 /tmp/repos/{issue_id}。
  • 解析 Issue 描述中的 Stack Trace 或測試失敗檔名，使用 Python ast 模組或 Tree-sitter 提取相關函式與類別的上下文資訊，壓縮 Prompt 長度以節省 Token。

3. LLM 補丁生成器 (src/solver.py)

  • 構建包含 Issue 描述、上下文 Code Snippets、與測試失敗訊息的 System Prompt。
  • 調用 Gemini API (如 gemini-2.5-pro) 生成修復補丁 (Unified Diff 格式)。
  • 自動將 Diff 應用於本地倉庫檔案 (git apply patch.diff)。

4. Docker 沙盒驗證 (src/tester.py)

  • 為確保安全與資源控制（避免占用過多 RAM），在輕量 Docker 容器內執行測試： 
    docker run --rm --memory=4g --cpus=2 -v /tmp/repos/{issue_id}:/app sandbox-runner pytest
  • 僅當容器內 100% 測試通過 (Exit Code 0) 時，才標記該解決方案為 READY_FOR_PR。

5. 自動提交與 PR (src/submitter.py)

  • 自動創建分支：git checkout -b fix/bounty-issue-{issue_id}。
  • 自動 Commit 並 Push 至 Fork 倉庫，透過 GitHub CLI 執行： 
    gh pr create --title "fix: resolve Issue #{issue_id}" --body "Automated fix verified by local test suite. Resolves #{issue_id}"

四、 Gemini CLI 自動執行指令腳本

請 Gemini CLI 直接執行以下步驟建立並運行系統：

# Step 1: 建立專案目錄結構
mkdir -p bounty_bot/config bounty_bot/src bounty_bot/docker

# Step 2: 安裝必要 Python 套件
pip install requests pyyaml pydantic google-genai GitPython

# Step 3: 建置主要入口點 main.py 並啟動輪詢服務
python main.py --daemon --interval 300

五、 運作機制與風險防護

  • 資源限制：限制本地最大並行 Docker 測試數量為 1，預留 12GB RAM 給系統運行。
  • 反垃圾機制：若測試未通過，絕對不提交 PR，維護 GitHub 帳號商譽與 Algora 權限。
  • 完全被動獲利：PR 被項目方 Merge 後，Algora 自動發放懸賞至綁定錢包/ Stripe 帳戶。
